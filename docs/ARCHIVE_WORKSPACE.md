# 档案工作台与运行开销

## 浏览方式

首页的技术文章、实验记录与次元收藏共用一套分类—列表—预览工作台。
点击记录只替换预览内容；全文和收藏图集仍通过独立 URL 打开。
桌面两块内容面板各自滚动，外框高度保持稳定。手机端列表改为横向档案条。

上下键切换记录，左右键切换分类，Home / End 跳到列表首尾，Enter 阅读。
同一浏览会话中保留各分类选中记录，分类切回不会重置选择。
快速选择取消旧预览动画，并从当前可见状态接续；不累积中间动画。
系统要求减少动态效果时直接完成切换。

视觉参考：

- [RhineLabUI](https://github.com/LBEILC/RhineLabUI)：分类与档案联动、固定阅读构图、灰白材质与刻度排版。
- [明日方舟官方网站](https://ak.hypergryph.com/)：信息层级、紧凑标签和档案语义。

未复制参考项目的 3D 模型、原片、音频或字体文件。角色图沿用本项目现有资源。

## 数据路径

- `GET /api/catalog`：仅选择索引字段；不查询或渲染 Markdown 正文。
- `GET /api/posts/:id`：按 slug 或 UUID 读取一条已发布记录。未发布或未来定时记录返回 404。
- 详情 HTML 缓存最多 32 个修订版本；版本由记录 ID 与更新时间区分。
- 首页在服务端取得索引快照，SSR 与 hydration 使用同一数据，客户端不重复请求。
- 原 `GET /api/posts` 保留兼容性；新的首页和详情读取流程不再依赖整库正文。

## 动画与布局

- 粒子和球体拆为按需加载模块，首页基础交互不包含其渲染实现。
- 球体采用绝对帧截止时间，保留帧间余数；最高 144 fps，实际受显示器和绘制耗时限制。
- 绘制成本过高时降低目标帧率，成本恢复后可重新提升，避免一次长任务永久锁定低帧率。
- 每帧旋转三角函数只计算一次，供全部顶点复用。
- 角色视差采用按经过时间计算的阻尼，在不同刷新率下保持相近响应速度。
- 当前章节、浏览进度、顶栏显隐和首屏视差共用一个滚动调度器。
- 章节位置只在尺寸或布局变化后重新测量；滚动时二分查找当前章节。
- 离开首屏、切到后台或进入简化动态模式时停止对应绘制。
- 内容面板采用实色层；导航只保留一层有限模糊，避免大面积叠加折射缓冲。

## 验证

`npm run typecheck:web` 单独检查实际 Web 代码，排除本机工作副本和未启用的 Worker 示例。
`tests/motion-math.test.mjs` 检查 60/120/144/240 Hz 调度、后台恢复、阻尼和双向章节定位。
`tests/public-catalog.test.mjs` 检查索引字段边界、参数化查询、公开状态过滤和修订缓存。

这些测试验证算法行为，不等同于所有设备的帧率保证。实际帧率还取决于 GPU、浏览器、窗口大小和同时运行的程序。
